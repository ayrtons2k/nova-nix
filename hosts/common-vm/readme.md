# Declarative NixOS Virtual Machine Environment

## 1. System Philosophy

This project utilizes a declarative virtual machine (VM) environment managed by a Nix flake. The system adheres to the "cattle, not pets" paradigm, which mandates the following principles:

- **Declarative State:** The entire configuration and state of a virtual machine are defined as code within `.nix` files. No manual, imperative changes are performed on a running instance.
- **Reproducibility:** Any team member with access to the Nix flake can build and execute an identical virtual machine, ensuring consistent testing and development environments.
- **Statelessness and Disposability:** VMs are treated as ephemeral artifacts. To update a VM's configuration, the source `.nix` file is modified, and the VM is rebuilt. The running instance is never altered directly. This practice guarantees a clean, predictable state for every execution.

## 2. System Architecture

The VM environment is composed of several integral components provided by the Nix ecosystem:

- **`flake.nix`**: The central entry point for the project. It defines all system outputs, including the set of available NixOS configurations for both host machines and virtual machines.
- **`nixos-rebuild build-vm`**: The primary NixOS tool used to realize a VM. It evaluates a specified NixOS configuration and compiles it into a bootable QEMU disk image artifact, along with a corresponding runner script.
- **QEMU**: The underlying, open-source hypervisor that executes the virtual machine. Interaction with QEMU is abstracted away by the runner script generated by `nixos-rebuild`.
- **9P Filesystem Protocol (`virtfs`)**: A feature of QEMU that enables high-performance directory sharing between the host and the guest operating system.

## 3. Directory Structure

All host-like configurations, including VMs and their shared base, are organized within the `hosts/` directory.

```
.
├── flake.nix                  # Central flake entry point; registers all VM configurations.
└── hosts/
    ├── common-vm/
    │   └── default.nix        # Base configuration SHARED by ALL VMs.
    ├── nova-nix/
    │   └── default.nix        # Configuration for the primary host machine.
    └── web-vm/
        └── default.nix        # Configuration SPECIFIC to the "web-vm" instance.
```

- `hosts/common-vm/default.nix`: This file serves as a **base profile** for all virtual machines. It contains the foundational NixOS settings required to make a configuration bootable and functional as a QEMU VM.
- `hosts/<vm-name>/default.nix`: This file defines the unique characteristics ("personality") of a specific VM. It **imports the `common-vm` profile** and adds its own specific services (e.g., Nginx), firewall rules, and QEMU execution parameters (e.g., memory, port forwarding).

## 4. Standard Operating Procedure

### 4.1. Build Phase

To build a virtual machine, execute the following command from the root directory of the flake. The `<vm-name>` must correspond to an output defined in the `nixosConfigurations` attribute set in `flake.nix`.

```bash
# Example for the 'web-vm'
nixos-rebuild build-vm --flake .#web-vm
```

_Note: If the VM's configuration uses an impure import, the `--impure` flag is required. See section 7.1 for the recommended pure alternative._

Successful execution generates a `result` symlink in the current directory, which points to the compiled VM artifacts in the Nix store.

### 4.2. Execution Phase

To run the built VM, execute the runner script located within the `result` directory. The script is named according to the `hostName` defined in the VM's configuration.

```bash
./result/bin/run-<vm-hostname>-vm
```

This will launch a QEMU instance. To terminate the VM, close the QEMU window.

## 5. Procedure for Creating a New VM

The instantiation of a new virtual machine is a declarative process:

1.  **Duplicate an Existing Configuration:** Copy the directory of an existing VM to serve as a template.
    ```bash
    cp -r hosts/web-vm hosts/new-vm-name
    ```
2.  **Modify the New Configuration:** Edit `hosts/new-vm-name/default.nix`. Adjust the `hostName`, services, and other parameters as required. Ensure the `imports` path (`../common-vm`) remains correct.
3.  **Register the New VM in `flake.nix`:** Add a new attribute to the `nixosConfigurations` set in `flake.nix`, pointing to the new configuration directory.
    ```nix
    # ./flake.nix
    nixosConfigurations = {
      # ... existing configurations
      "new-vm-name" = nixpkgs.lib.nixosSystem {
        system = "x86_64-linux";
        modules = [ ./hosts/new-vm-name ];
        # ... specialArgs if needed
      };
    };
    ```
4.  **Build and Execute:** Follow the Standard Operating Procedure (Section 4) using the new VM's name (`new-vm-name`).

## 6. Configuration Management and Enhancement

All modifications to a VM's configuration must be performed on the source `.nix` files.

**Procedure:**

1.  Ensure the target VM is not running.
2.  Modify the appropriate `.nix` file (`hosts/<vm-name>/default.nix` for specific changes or `hosts/common-vm/default.nix` for global changes).
3.  Rebuild and execute the VM as described in Section 4 to apply the changes.

## 7. Recommended Practices

### 7.1. Maintaining Flake Purity

For modules that are not automatically loaded (like `qemu-vm.nix`), a manual import is necessary. To avoid the impure `"<nixpkgs/...">` syntax, use `specialArgs`.

**1. In `flake.nix`:** Pass the `nixpkgs` input to the module system.

```nix
"web-vm" = nixpkgs.lib.nixosSystem {
  # ...
  specialArgs = { "flake-nixpkgs" = nixpkgs; };
  modules = [ ./hosts/web-vm ];
};
```

**2. In `hosts/web-vm/default.nix`:** Accept the argument and use it for a pure import path.

```nix
{ config, pkgs, flake-nixpkgs, ... }:
{
  imports = [
    ../common-vm
    "${flake-nixpkgs}/nixos/modules/virtualisation/qemu-vm.nix"
  ];
  # ...
}
```

This approach eliminates the need for the `--impure` flag.

### 7.2. Workflow Automation

For frequently used VMs, consider creating a helper script (e.g., `run-vm.sh`) in the project root to automate the build and execution sequence.
